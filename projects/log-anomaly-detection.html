BACKGROUND

연구 배경과 기존 방법의 한계

  • 연구 목적: 대규모 시스템 로그에서 이상 징후를 감지해 안정적인 운영 지원
  • DeepLog: LSTM을 활용한 로그의 순차 흐름 학습
  • LogBERT: Drain으로 로그를 템플릿화한 후 Transformer로 문맥 학습
  • 정보 손실: 템플릿화 과정에서 파라미터·경로·수치 등 세부 정보 제거
  • 의미 표현의 한계: 랜덤 임베딩만으로 유사 로그 간 의미적 관계 반영 어려움
  • 빈도 정보 부재: 특정 이벤트가 급증하는 로그 폭풍(Log Storm) 포착에 한계
CONTRIBUTION

의미와 발생 빈도를 함께 반영하는 복합 임베딩

  • Event Template: 로그 시퀀스의 거시적 의미
  • Semantic ID: 원시 로그의 세부 의미
  • Frequency: 이벤트 발생 빈도의 양적 변화
  • 세 관점을 독립적으로 임베딩하고 결합해 기존 랜덤 임베딩의 한계 보완
  • HDFS·BGL·TBird에서 성능 및 데이터셋별 임베딩 기여도 검증
PROPOSED METHOD

세 가지 임베딩과 결합 구조

01 · Event Template Embedding

  • Drain으로 추출한 이벤트 템플릿을 Sentence-BERT로 인코딩
  • 의미가 유사한 템플릿 사이의 상관관계를 벡터로 표현
  • 로그 시퀀스의 거시적 흐름과 문맥적 의미 전달

02 · Frequency Embedding

  • RLE(Run-Length Encoding)로 동일 이벤트의 연속 발생 횟수 추출
  • 예: [1, 1, 2, 2, 3] → [2, 2, 2, 2, 1]
  • MLP로 학습 가능한 벡터로 변환해 로그 폭풍과 같은 양적 이상 패턴 반영

03 · Semantic ID Embedding

  • 원시 로그 전체를 Sentence-BERT로 인코딩
  • 계층적 잔차 양자화와 코드북으로 이산 Semantic ID 생성
  • 각 단계에서 가까운 코드북 벡터의 인덱스를 순차 할당
  • Semantic ID를 MLP로 변환해 파서가 제거한 세부 정보 보존

04 · Embedding Fusion

  • 세 임베딩을 동일한 차원으로 구성
  • 원소별 덧셈(Element-wise Addition)으로 결합
  • 차원 팽창 없이 단일 벡터에 정보를 중첩한 뒤 LogBERT에 입력
MY ROLE

담당 역할

  • 방법론 설계: 의미·빈도 정보를 함께 반영하는 임베딩 구성과 결합 방식 제안
  • 실험: HDFS·BGL·TBird 벤치마크 검증 및 임베딩 조합 비교
  • 협업: 국방과학연구소·LIG넥스원 공동연구
EXPERIMENTS

실험 결과와 데이터셋별 차이

  • BGL: Baseline 40.997 → 제안 방식 61.797, 20.800p 향상
  • TBird: Baseline 87.790 → 제안 방식 90.393, 2.603p 향상
  • HDFS: Event Template 단독 사용 시 79.223으로 최고 성능; 제안 방식은 77.037
  • Frequency 단독 추가: BGL 40.997 → 55.393, 약 14.4p 향상
분석 인사이트
  • 로그 폭풍 환경에서는 빈도 정보가 중요: BGL에서 Frequency Embedding의 기여 확인
  • 세부 의미 보존의 효과: Semantic ID를 추가한 최종 조합이 BGL·TBird에서 최고 성능
  • 복합 임베딩이 항상 최선은 아님: 구조가 정형화된 HDFS는 Event Template만으로 높은 성능
  • 데이터셋 특성에 맞춘 설계 필요: 로그 다양성과 반복 패턴에 따라 임베딩 기여도 차이 발생
